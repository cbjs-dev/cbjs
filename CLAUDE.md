# CLAUDE.md

Cbjs is a **type-augmented reimplementation of the official Couchbase Node.js SDK**
(`couchbase` / "couchnode"). It's a drop-in, ESM-native replacement that ports the
official SDK's runtime and layers on TypeScript DX (inferred KV return types,
branded keyspaces, `ClusterTypes` generics, chainable `lookupIn`/`mutateIn`).

## Monorepo

pnpm workspace (pnpm only — `preinstall` enforces it). Lerna runs builds.

| Package | Role |
|---|---|
| `@cbjsdev/shared` | **Zero runtime deps.** Types + utils. Base of the graph — must never import cbjs. |
| `@cbjsdev/cbjs` | The SDK. Ships the native binary. Mirrors couchnode `lib/`. |
| `@cbjsdev/http-client` | Typed Couchbase management HTTP client. |
| `@cbjsdev/deploy` | Cluster deployment utils. |
| `@cbjsdev/vitest` | Test harness + fixtures (`createCouchbaseTest`, `ServerTestContext`). |
| `tests/*` | Separate workspace packages (e.g. `test-project-cbjs`) holding integration tests. |

Dep direction: `shared` ← `http-client`/`cbjs` ← `deploy`/`vitest`/`tests`.

## Conventions (must-follow)

- **ESM + `moduleResolution: node16`** → every relative import needs the explicit
  `.js` extension (`import { x } from './foo.js'`), even from `.ts`.
- Prettier (semicolons, 2-space) + `@trivago/prettier-plugin-sort-imports` auto-sorts
  imports — don't hand-order them; run `prettier --write` on touched files. Husky runs it pre-commit.
- `verbatimModuleSyntax` is **off**; prefer `import type` for type-only imports anyway.
- Apache-2.0 license header on every source file (Jonathan MASSUCHETTI + Couchbase Inc.).
- Public API barrel is **`packages/cbjs/src/index.ts`** (upstream uses `couchbase.ts` as
  the barrel — cbjs does not). `internal.ts` is the internal barrel.
- Heavy generics everywhere: `Cluster<T extends CouchbaseClusterTypes>`, branded
  `BucketName<T>`/keyspaces, `DefaultClusterTypes`.
- Errors derive from `CouchbaseError`; `errorFromCpp(cppErr)` converts native errors.
  KV ops reject with the **raw** `CppError` and convert in a `catch`.
- Anything the server only offers from a given version on — an API, an option, a response
  field — carries a JSDoc **`@since Couchbase Server <x.y>`** tag (e.g.
  `@since Couchbase Server 8.0`). Spell out "Couchbase Server": `@since` alone reads as a
  cbjs version. The CI matrix (7.2 / 7.6 / 8.0) is what makes this actionable — an
  untagged field that older servers omit fails there, so type it optional **and** tag it.
  The tag says it once: never restate the version in the prose above it.

## Build / typecheck / test

- **Node 22** (`.nvmrc` → `22.21.1`); vite 8 / vitest 4 require `^20.19 || >=22.12`.
- Per package: `npx tsc -p tsconfig.build.json` (emit) or `--noEmit` (typecheck).
  `tsconfig.build.json` excludes `*.spec.ts` / `*.spec-d.ts`. Root tsconfig is
  `strict` + `noEmitOnError`. **cbjs typecheck is large/slow — allow generous time.**
- Consumers resolve `@cbjsdev/cbjs` via its built `dist/` (package `main`).
  **Rebuild cbjs before typechecking `deploy`/`vitest`/`tests` against source changes.**
- Unit tests: `packages/*/src/*.spec.ts`, vitest, `environment: node`, **no cluster** →
  `npx vitest run <file>`.
- Type tests: `*.spec-d.ts` via `npx vitest --typecheck run` (`expectTypeOf`).
  (vitest 4 doesn't forward `--typecheck` to project configs, so `vitest.shared.packages.ts`
  reads the flag off `process.argv` itself — keep that shim if you touch that config.)

## Upstream sync (core workflow)

`packages/cbjs/src/*` **mirrors couchnode `lib/*` 1:1** (collection.ts, cluster.ts,
binding.ts, …). Cbjs ports the official SDK's TS layer and augments it.

- **`latest-upstream-commit`** (repo root) is the sync ledger: which couchnode **master**
  commits are incorporated, grouped by version, newest-first, with `OK`/`WIP`/`nothing to do` notes.
- couchnode uses release branches; **master and version tags diverge.** Cbjs tracks the
  **master** commit stream — a tag like `v4.6.1` can be a release-branch-only patch not on master.
- When syncing: **don't blind-patch.** Analyze each feature and apply it the cbjs way
  (great DX + TS). Skip pure-format commits (couchnode ESLint reflows) — cbjs has its own prettier.
- `binding.ts` is the autogenerated mirror of the **native addon ABI** — it must match the
  installed binary version.

## Native binary (gotcha)

cbjs ships the official SDK's `couchbase-native.node`, fetched by
`packages/cbjs/scripts/install.mjs <version>` from npm (`@couchbase/couchbase-<platform>-<arch>-napi`).

- Version is pinned in `packages/cbjs/package.json` → `scripts.install`, and must match
  `binding.ts`'s ABI. Keep `src/version.ts` `couchnodeVersion` in sync.
- After bumping: `rm -f src/couchbase-native.node dist/src/couchbase-native.node && pnpm install`
  (the install script skips if a binary is already present).

## Integration tests need a live cluster

`tests/cbjs/tests/*.spec.ts` require a running Couchbase. Connection comes from env:
`CB_CONNECTION_STRING`, `CB_USER`, `CB_PASSWORD` (read by `getConnectionParams()`).

- **Always `docker ps` first** — a cluster is usually already running locally
  (e.g. `couchbase-8.0.0`, ports `8091-8097` published). Reuse it; don't spin up a duplicate.
- Fresh cluster (mirrors CI, see `.github/workflows/tests.yml`): run
  `couchbase:enterprise-*` in docker, then `pnpm dlx tsx tests/scripts/initTestCluster.ts`
  with `Administrator`/`password`.
- Harness: `const test = await createCouchbaseTest(); test(name, async ({ serverTestContext, expect }) => …)`.
  `serverTestContext` gives an ephemeral bucket/keyspace with auto-cleanup;
  `serverTestContext.newConnection(params?, opts?)` accepts `ConnectOptions` (e.g. a custom `tracer`);
  `serverTestContext.getKeyspace()` → `{ bucket, scope, collection }`.
- Tests create/drop `cbjs_*` buckets. **Never touch the `pragma` bucket** (real data);
  clean up any leftover `cbjs_*` buckets you create.

## Observability (4.7.0+)

- The **public observability contract** (`RequestTracer`, `RequestSpan`, `Meter`,
  `ValueRecorder`, `SpanStatus`, `SpanStatusCode`, `AttributeValue`, `TimeInput`, `HiResTime`)
  lives in **`@cbjsdev/shared`** (`couchbase/types/observability.types.ts`). cbjs re-exports it
  (tracing.ts / metrics.ts / observabilitytypes.ts / binding.ts) so its public API is unchanged.
- These interfaces are **byte-identical to the official SDK's**, so a tracer/meter is
  interchangeable between cbjs and `couchbase`.
- Per-op tracing: KV threads through `Collection._observeKvCall`, query through the
  `queryexecutor` handler wrap. `ObservableRequestHandler` lifecycle is
  `new → setRequest*Attributes → wrapObservableBindingCall → end()/endWithError()` (idempotent).
  Every op options type carries `parentSpan?: RequestSpan`.
- Telemetry adapters (e.g. `@cbjsdev/telemetry-sentry`) type-depend on **`@cbjsdev/shared` only**
  (never cbjs), inject the vendor SDK, and ship zero runtime deps — so they work with the
  official SDK too, without the native binary.
- Status: KV + query are traced; search/analytics/views/management + replica streaming + OTel
  adapters are still pending (tracked in `latest-upstream-commit`).
